## 为什么不是直接刷题

行测真题的难点从来不是"没做过"，而是**做过的第 8 天就忘了**。本应用的核心不是题库，而是那套排程：

- 每道题有独立的记忆状态（稳定性、难度、复习次数、上次结果）
- 到点才推给你，不到点绝不打扰
- **答错或忘记的题会自动缩短间隔**，反复出现直到稳住
- 你只需做一件事：答完自评"我记住了多少"

题库只是载体，真正的产品是**复习的那条时间线**。

```bash

cd GongkaoNaoku
python3 assemble_db.py   # 合并分卷题库，生成 kaogong.db（约 10 秒）
```

浏览器打开 <http://127.0.0.1:8300>。

> **Windows 用户**：直接双击 `启动考公系统.bat`，浏览器会自动打开。关掉那个黑色窗口即停止服务。
> **Linux / macOS**：`bash start.sh`。

首次打开会让你选择：**注册账号**（换设备也能接着学）或 **游客模式**（点一下直接用，不填任何信息）。

> 只需要 Python 3.8+，**运行时零第三方依赖**（不装 Flask、不装 ORM、不连 CDN）。

## 一次完整的复习长什么样

四步说清楚：

1. **首页**：顶上是今日任务——待复习 N 道、未学新题 M 道、今日已练、错题本与收藏数；左边栏六个模块的进度条，下面是掌握度分布（学习中 / 初记 / 短期 / 长期 / 稳固）。
2. **进「复习到期」**：直接出题。题目上方是面包屑（模块 / 地区+年份 / 考点）与「标记」「查看完整标注」；资料分析题会先展开「给定材料」，可折叠；下面是题干与 A–D 选项。
3. **自己作答**：点选项即判对错——选对的选项变绿并标「✔ 正确」，选错的变红、正确项同时高亮；随后展开「问法模型 / 推理链 / ⚡最快解法 / ⚠易错点 / 🧩母题抽象 / 官方解析」，工具栏可收藏、写笔记、看完整标注。
4. **四档自评**：忘记 / 困难 / 一般 / 熟悉。评完立刻跳下一题，6 秒内可撤销；评「忘记」时这道题会被插回队列第 3 题之后，几分钟内真的会再见到。

其余视图都是这个流程的变体：错题本、我的收藏、材料组题、疑点复核、考点导航只是换一个「题池」；模拟考试沿用同一套作答界面，另加顶部倒计时与题号跳转；数据统计与设置各自独立。

外观支持暗色 / 亮色 / 跟随系统三态、字号 14–19px 可调、专注模式（隐藏侧栏、居中窄列）。

| 模块 | 做什么 |
| :--- | :--- |
| **总览面板** | 今日待复习 / 未学新题 / 已练 / 错题数 / 收藏数，各模块进度条，掌握度分布（学习中·初记·短期·长期·稳固） |
| **开始练习** | 按模块 / 大类 / 考点筛选出新题，逐题作答 → 看深度标注 → 自评记忆强度 |
| **复习到期** | 记忆引擎推送的当日复习队列。与新题流程一致：先看选项自己作答，再核对正确答案与解析，最后自评熟悉度 |

| **模拟考试** | 两种组卷方式：**真题整卷**（选地区/年份/试卷，把当年那一整份卷子原样抽出来，题量、模块构成、卷面顺序都对得上）和**快速组卷**（按模块/题量/时长随机抽）。题面按真实卷面模块顺序排列（政治理论 → 常识 → 言语 → 数量 → 判断 → 资料），交卷按模块加权算分并给出各模块成绩单；中途关掉浏览器也能**断点续考**，历史记录里能翻出当时的答题卡 |
| **材料组题** | 资料分析按同一段材料成组出题（702 组标准 5 题组）；练习新题时也会自动整组带出，不用反复重读材料 |
| **疑点复核** | 汇总所有标注「官方解析可能有误」的题，逐条复核并标记 |
| **数据统计** | 连续打卡天数、每日目标环、近半年热力图、各模块正确率、薄弱考点排行、**自评偏差**（自评记住了但其实选错）、顽固题清单 |
| **真题浏览** | 六模块全量筛选：地区 / 年份 / 关键字 / 复习状态 / 下次复习日 |
| **考点导航** | 按考点横向对比不同省份的同类考法，一键「练同类题」 |

**外观**：主题三态循环（暗色 / 亮色 / 跟随系统）、字号 14–19px 可调、专注模式隐藏侧栏居中窄列。

**键盘流**：作答时 `A/B/C/D` 选选项，`空格` 看标注；自评 `1/2/3/4` 对应 忘记/困难/一般/熟悉。

## 每道题都带什么

不是只有题干和答案。解析由程序从原始题库逐题抽取，每道题包含：

`问法模型` · `推理链` · `⚡最快解法` · `⚠易错点` · `🧩母题抽象` · `给定材料` · `官方解析` · `❓疑点待复核` · `📝个人笔记` · `⭐收藏`

当前库统计：含图题 10,647 道（38.7%，配图 39,692 张 / 约 192MB，全部本地化、断网可看），带疑点标注 1,577 道，带材料分组 7,327 道（1,170 组，其中 861 组为 2–6 题的可用整组、702 组是标准 5 题组），不同考点 10,552 个。

## 记忆引擎：FSRS-5 怎么运作

作答后按真实记忆强度自评四档，系统据此重算这道题的**下次出现时间**。引擎是 FSRS-5（不是 SM-2）：它把记忆拆成**稳定性 S**（这条记忆能保持多久）和**难度 D**（这道题对*你*有多难）两个变量，再用「当前还能记住的概率 R」决定间隔 —— 同样点「一般」，隔很久还记得就大幅拉长，刚忘过就少涨。

| 自评 | 含义 | 引擎行为 |
| :--- | :--- | :--- |
| **忘记** | 完全没印象 | 1 分钟后再出现（学习步第 1 档），稳定性大幅下降、难度上升 |
| **困难** | 想起来了但很吃力 | 学习期停在本步重来；复习期稳定性增长只拿 23% 折扣 |
| **一般** | 正常记住 | 学习期前进一步（1 分钟 → 10 分钟 → 毕业 1 天）；复习期标准增长 |
| **熟悉** | 轻松秒答 | 跳过剩余学习步直接毕业（4 天）；复习期增长再乘 3 倍奖励 |

四条容易被忽略的细节：

- **学习步**：新题与遗忘题不是「当天随便再抽到」，而是 1 分钟 → 10 分钟两步，走完才毕业成 1 天。评「忘记」时这道题也会被插回当前队列的 3 题之后，几分钟内真的会再见到。
- **间隔上限 60 天**：FSRS 在「全熟悉」时会把间隔推到几百天（它假设你的目标是终身保留）；考公是几个月的冲刺，几百天后再见等于没复习。顽固题（遗忘 ≥8 次）更严，封顶 30 天。
- **间隔抖动**：间隔 ≥3 天时按 ±5%（至少 ±1 天）抖动。否则同一天学的题会永远同一天到期，学 100 道新题，6 天后一次性涌来 100 道复习。
- **每日上限**：默认每日新题 20 / 复习 200，超量顺延到明天（设置页可改，填 0 不限量）。一天刷太多新题，第二天会被积压的复习埋掉。

典型间隔序列（每步都按时复习）：全「一般」是 **1 → 3 → 8 → 20 → 47 → 60** 天；全「熟悉」是 **4 → 29 → 60** 天。

## 多账号与隐私

服务端按账号隔离数据，一套部署可多人使用，互不可见。

| 身份 | 说明 |
| :--- | :--- |
| **注册账号** | 用户名 + 密码登录（PBKDF2-HMAC-SHA256 加盐哈希），凭账号在任何设备续上进度 |
| **游客模式** | 免注册进入，自动获得一个云端匿名身份；**换浏览器或清缓存即为全新身份**。设置页可随时升级为正式账号，数据不丢；退出即销毁，不留残留 |

题量与进度都存放在服务端 SQLite，浏览器只保存一枚登录令牌。

**内置的防护**（v1.8.0 起，开箱即生效）：

| 项 | 做法 |
| :--- | :--- |
| 令牌传递 | 只走 `Authorization: Bearer <token>` 请求头，不进 URL、不进 body —— URL 会留在浏览器历史、反代日志和 `Referer` 里 |
| 跨域 | 只对同源请求回 CORS 放行头；第三方站点既发不出带登录态的请求，也读不到响应 |
| 登录限流 | 同 IP 10 分钟失败 20 次、或同 IP+账号失败 10 次即锁定；失败额外延迟 0.25 秒 |
| 其它接口限流 | 注册 20 次 / 游客身份 30 次 / 改密 10 次（均按 10 分钟计） |
| 错误信息 | 500 只返回固定文案 + 一个 `ref`，异常栈只写服务端日志 |
| 请求体 | 超过 2MB 直接 413；`Content-Length` 非法直接 400 |
| 响应头 | `nosniff`、`X-Frame-Options`、`Referrer-Policy: no-referrer`、`Permissions-Policy`、`COOP`、CSP；经 HTTPS 反代时自动加 HSTS |

> 对外提供服务前请先读 [部署到自己的服务器](#部署到自己的服务器可选) 里的加固清单——默认配置面向本机 / 可信局域网。

## 配置

全部走环境变量，默认值开箱即用：

| 变量 | 默认 | 用途 |
| :--- | :--- | :--- |
| `PORT` / `KAOGONG_PORT` | `8300` | 服务监听端口 |
| `KAOGONG_VAULT` | `../kaogongzhentizhengliu-main` | 原始题库 Vault 路径 |
| `KAOGONG_FRESH` | 未设置 | 设为 `1` 完全重建数据库（**清空学习进度**） |
| `OPS_TOKEN` | 未设置 | 运营面板访问口令，**至少 16 位**才生效；不设则 `/ops` 整站 404 |
| `OPS_HIDE_ANON` | `1` | 运营面板默认只统计正式账号；设 `0` 则把游客也算进来 |
| `TRUST_PROXY` | `0` | 设为 `1` 才采信 `X-Forwarded-For` 取真实 IP。**只有确实在反向代理后面才开**，否则该头可被伪造，限流等于失效 |
| `MAX_BODY_BYTES` | `2097152` | 请求体上限（字节），超过直接 413 |

题库更新后重跑 `python3 parse.py` 即可增量导入：进度以题号（`qid`）为准自动保留，只有新增的题会以「未学」进入计划。

## 运营面板（只读）

给站长看的一张数据看板，**只读、只聚合、不碰任何用户学习内容**。

**开启方式**（不设口令时整个面板连"存在"都不暴露，直接 404）：

```bash
OPS_TOKEN="改成你自己的至少16位随机串" python3 server.py
# 然后访问 http://127.0.0.1:8300/ops
```

生成口令：`python3 -c "import secrets;print(secrets.token_urlsafe(24))"`

### 看什么

| 区块 | 内容 |
| :--- | :--- |
| 指标卡 | 今日活跃 / 今日答题 / 正式账号数 / 今日新增，各带 7 天、30 天对照 |
| 答题活跃度 | 按天柱状，悬停看当日人数；区间可选 7 / 30 / 90 天 |
| 新增账号 | 按天柱状，悬停区分正式与游客 |
| 用户做题量分布 | 100+ / 30-99 / 10-29 / 1-9 / 0 题五档人数与占比 |
| 最近活跃账号 | 近 7 天有答题的账号，只显示昵称、类型、最近答题时间、累计题量 |
| 题库与存储健康 | 题量、完整性自检、进度行数、缺解析题数、库文件大小、日志模式、模块分布 |

### 安全设计

| 措施 | 说明 |
| :--- | :--- |
| 口令不进代码 | 只从 `OPS_TOKEN` 环境变量读；少于 16 位视为未配置 |
| 会话与用户体系隔离 | 面板会话只存进程内存（8 小时过期、上限 32 个），**普通用户 token 无效** |
| 暴力猜解防护 | 同 IP 10 分钟内 8 次失败即锁；每次失败额外延迟 0.4 秒；常数时间比对 |
| Cookie | `HttpOnly` + `SameSite=Strict` + `Path=/ops` |
| 接口只读 | 全部接口只有 `SELECT`，**没有任何写库路径** |
| 页面不被收录 | `<meta name="robots" content="noindex,nofollow">` |

> 面板重启即失效（会话在内存里），部署更新后需要重新输入口令，属预期行为。

## 部署到自己的服务器（可选）

本仓库只描述**自托管**。想分享给同学一起用，把它跑在自己的服务器 / 家里的小主机上即可。

### 1. 准备

- Python 3.8+（无第三方依赖）
- 约 350MB 磁盘（题库分卷 148MB + 配图 192MB + 用户库）
- 建议 1 核 1GB 内存起步

```bash
git clone git@github.com:Hodgeli/GongkaoNaoku.git /srv/kaogong
cd /srv/kaogong
python3 assemble_db.py
PORT=8300 python3 server.py
```

### 2. 开机自启（systemd 用户服务）

`~/.config/systemd/user/gongkao.service`：

```ini
[Unit]
Description=Kaogong Naoku
After=network.target

[Service]
WorkingDirectory=/srv/kaogong
Environment=PORT=8300
ExecStart=/usr/bin/python3 /srv/kaogong/server.py
Restart=always

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now gongkao.service
loginctl enable-linger "$USER"    # 注销后仍保持运行
```

### 3. 日常更新

仓库自带 `sync.sh`，把「提交 → 推送 → 重启服务」串成一条命令：

```bash
./sync.sh push "改了点什么"   # 提交全部改动 → push origin → 重启并做 HTTP 探测
./sync.sh pull                # 拉取远端更新（rebase）→ 重启
./sync.sh restart             # 只重启（改完 server.py 用这个）
```

服务名与端口可用环境变量覆盖：`KAOGONG_SERVICE` / `KAOGONG_BRANCH` / `KAOGONG_PORT`。

### 4. 备份（唯一要备份的文件）

**只备份 `users.db`。** 题库 `kaogong.db` 是只读的、随时可由分卷重建；你的账号、做题记录、收藏、笔记、复习进度全在 `users.db` 一个文件里。

```bash
sqlite3 users.db ".backup '/backup/users-$(date +%F).db'"   # 热备份，不停服
# 或者直接 cp users.db /backup/ （建议先停服）
```

换机恢复：拷回 `users.db` → `python3 assemble_db.py` → 启动服务，进度原样接上。

### 5. 挂公网前请务必加固

默认配置面向**本机或可信局域网**。如果要直接暴露到公网，至少做到：

| 项 | 做法 |
| :--- | :--- |
| HTTPS | 前置 Nginx / Caddy 做 TLS 终止，别让明文口令上网。经反代时记得设 `X-Forwarded-Proto: https`（服务会自动加 HSTS） |
| 反向代理 | 只反代 `127.0.0.1:8300`，服务本身不要监听 `0.0.0.0`；反代加了 `X-Forwarded-For` 后，服务端设 `TRUST_PROXY=1` 才能拿到真实 IP，否则所有人共用反代 IP、限流会互相牵连 |
| 注册控制 | 若只给自己和同学用，考虑在反代层拦掉 `/api/auth/register`，或加白名单 |
| 登录限流 | 服务端已内置（IP 20 次 / IP+账号 10 次 / 10 分钟）；反代层再加一层 `limit_req` 更稳 |
| 备份 | 配一个定时任务把 `users.db` 备份到别处，别只留一份 |
| 日志 | 反代访问日志会记录 URL —— 令牌已改走请求头，日志里不会出现凭证；仍建议别把 `Authorization` 头也记进去 |

> 更细的部署与排障记录不随仓库提供（含个人环境信息），需要时看本机笔记。

## 常见问题

**换浏览器后进度不见了？**
注册账号后用用户名登录即可续上。游客模式的身份绑定在浏览器本地，换设备即为新身份——这是设计如此，不是丢数据。

**能不能多人共用？**
可以。各自注册账号，学习进度、笔记、收藏完全隔离，互相看不到对方的存在。前提是**你自己部署的实例**，并且按上一节做了基本加固。

**占多大地方？**
代码不到 200KB。题库数据库（约 148MB，30MB×5 分卷）与配图（约 192MB）随仓库提供，**`git clone` 全部到手**，克隆后跑一次 `python3 assemble_db.py` 合并数据库即可，无需自备题库。你的学习数据另存于 `users.db`，首次启动自动生成、初始不到 1MB。

**需要联网吗？**
运行完全不需要。零第三方依赖、零 CDN、零外部字体，断网照常用。

**上游题库 58,890 题，为什么这里只有 27,506 题？**
上游的 58,890 是「题目行数」——联考同一道题会以几十个省卷的名义重复收录（平均每题 2.32 套卷，最多一道被 778 套卷收录）；按题去重后上游只有 25,382 道不同的题，本项目覆盖其中 25,271 道（**99.56%**），另有 158 道上游没有的更早年真题。不是漏题，是把「卷 × 题」去重成了「题」，更适合刷题与复习。逐题核查的完整表格见 [素材来源与致谢](#素材来源与致谢)。

**数据里有脏数据吗？**
现在**没有了**：27,506 道题全部有选项、有答案，资料分析全部带材料。

v1.8.1 修完了源库遗留的 18 处缺陷——13 道资料分析缺「给定材料」（材料是图表图片，已从上游 [ERRRC/xingcezhenti](https://github.com/ERRRC/xingcezhenti) 取回并接入本地图库）、5 道判断题缺选项（补 `A.正确 / B.错误`，答案取自原文解析结尾的「故表述错误」）。

这些修正放在 `data/fixups.json`，由 `assemble_db.py` 合并分卷后、`parse.py` 导入后自动套用——因为 `kaogong.db` 是构建产物不进版本库，只有这样才能让修正跟着仓库走。你自己发现的错题也可以往这个文件里加一条，格式见文件开头的 `_说明`。

**升级后我的进度会丢吗？**
不会。题库（`kaogong.db`，只读）与用户数据（`users.db`）自 v1.1 起分库存放，更新题库、重建 `kaogong.db` 都不会碰到进度；新版本启动时会自动给 `users.db` 补缺失的列（幂等 `ALTER TABLE`）。

## 题库数据从哪来（已随仓库提供）

`kaogong.db` 纯题库（约 148MB，30MB 分卷随仓库提交）和 `90-图片/`（约 192MB）已经随仓库提供，**克隆即可用，里面已含 27,506 道题**；你的学习数据存于 `users.db`，首次启动服务时自动生成。

题库收录自公开渠道整理的「考公真题整理」Vault——**506 份试卷、2008–2026 年、31 个省区市 + 国考 + 选调 + 联考**的行测真题，试卷以各考试当年考生回忆版为基础整理。详细构成与完整地区/年份分布见上文 [题库来源明细](#题库来源明细)。

```bash
git clone git@github.com:Hodgeli/GongkaoNaoku.git
cd GongkaoNaoku
python3 assemble_db.py   # 合并分卷题库 → kaogong.db
python3 server.py
```

仅当你**想从原始题库更新内容**时才需要 `parse.py`：设置 `KAOGONG_VAULT` 指向原题库 Vault 后运行，产出纯题库——学习进度存于 `users.db`，与题库更新完全无关。
